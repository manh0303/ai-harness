# accessible-ui

## Input
Approved screen/flow, design system components and API contract.

## Procedure
1. Map loading, empty, error, success and disabled states.
2. Implement semantic controls, labels, keyboard access and focus transitions.
3. Handle stale requests and unmount cleanup without duplicate effects.
4. Test by visible user behavior and exercise critical flows in a browser.

Use core TDD, debugging and review procedures for the common development lifecycle.

## Output
UI changes plus state/accessibility and browser evidence.

## Constraints
Do not replace the design system or fabricate missing product decisions.
