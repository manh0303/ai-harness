# Project artifact contracts
## Problem
Projects need explicit inputs, outputs, destinations, canonical ownership and source-edit policies.
An idea must lead to proportional software docs at the user's chosen storage; existing sources must
be preserved or updated within declared scope. Tool links alone neither connect nor authorize tools.
## Result
Seed project-owned artifacts.json/integrations.json, expose read-only setup/reporting, route local
docs or return external handoffs, and review artifact maintenance with each OpenSpec change.
## Scope
CLI validation/install/setup/new-doc/readiness, Core discovery/workflows/checks/evals, Product/UIUX
handoffs, docs, package smoke and tests. No network client, secret storage or MCP/connector runtime.
## Authorization
The project owner requested a PR implementing this contract and a release/npm publication in this session.
