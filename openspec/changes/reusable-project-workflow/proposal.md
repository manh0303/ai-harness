# Reusable project workflow

## Why
Reference-project feedback identifies daily task selection, repeated discovery and interrupted
verification/docs as pain points. The user requires reusable support across projects and AI tools.

## Result
Add read-only status/changes, selecting an existing proposal via start --change, backed-up intake
clear, declared file references in command arguments, optional knowledge index/workflow and
recoverable verification with incremental evidence/docs. Compose existing task/checkpoint/artifact
contracts rather than importing project-specific state fields, scripts, paths, credentials or tools.

## Scope
The existing portable-host change selects one tool. No process runner, mandatory knowledge tree,
new skill dependency, automatic archive, role seeding, model call, merge or release. User requested
code updates and preparing a reviewable PR; actual client compliance remains unverified.
