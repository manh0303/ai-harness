# Frontend/mobile coding and simpler onboarding

## Why
Quick start buried host/preset setup and the CLI table omitted implemented flags. React/Next.js and
React Native each exposed only two risk-specific skills, leaving ordinary route/screen/form/data work
and stack-specific verification without a concise procedure.

## What changes
Put host choice and a setup prompt in onboarding, surface current flags, and add feature/screen delivery
plus behavior-testing skills to the two existing adapters. Reuse Core TDD/review, conventions, manifests
and the installer. Add examples/checklists/handoffs, manual checks/unscored scenarios and real package
asset/install/update evidence. Keep architecture/library choices grounded in consumer source.

## Non-goals
No application scaffolder, framework dependencies, test runner or model/agent orchestration runtime.
No router/state migrations, publication, or inference of browser/native/model success from structural tests.
