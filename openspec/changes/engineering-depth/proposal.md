# Engineering and technical-document depth

## Problem
The user authorized all six proposed groups: coding, architecture, feature TechSpec, stack depth,
verification and documentation/export. Existing skills cover the lifecycle but lack some actionable
invariant, refactor, version-aware optimization and rendered-document QA detail.

## Scope
Deepen existing IDs and reuse spec-to-code/OpenSpec. Add one common routing extension, three declared
adapter engineering rules and one optional Product export workflow. Expand original architecture/
TechSpec guidance, add checks/evals and a pinned reference inventory. No upstream source vendoring,
new runtime, dependencies, installer execution, model calls, automatic merge/publish or extra agents.

## Acceptance
See specs/engineering/spec.md. Default Core remains sufficient for coding; optional modules stay
selected. Word/PDF/slides are host-executed instructions, not bundled exporters. Preserve user docs.
