# Progress, feedback and scope changes

1. Read actual completed check/PR evidence against the current plan; do not infer completion from tasks alone.
2. Maintain risk-register with source, confirmed/proposed owners, triggers and unresolved external dependencies.
3. For changed scope load scope-change: preserve baseline, consult BA/PO/SA/DevOps as relevant, compare
   defer/replace/expand and resolve material choices. Continue independent already-authorized work.
4. Update affected plan, requirements, ADRs and OpenSpec only after the actual decision; keep history.
5. Produce a status draft with completed/pending/blocked work and evidence. Release ownership/gates
   remain in DevOps; PM proposals do not approve delivery or production changes.
