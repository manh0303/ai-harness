# Reviewed outcome → delivery plan

Input: agreed scope/MVP, acceptance, solution boundaries and known team constraints.
1. Read Core solution-framing and existing approved plan; choose compact or full depth.
2. Load harness-delivery-planning for usable vertical slices, dependencies, repository order and gates.
3. Use actual team estimates/capacity; without them document sequencing and missing estimate owners,
   not fabricated milestones. Compare scope trade-offs with PO and technical dependencies with SA.
4. Load risk-management for owned risks/blockers/assumptions/dependencies and response triggers.
5. Link plan to requirements/ADRs/OpenSpec tasks and DevOps rollout/rollback. Actual owner reviews
   consequential commitments; explicit authorization already covering routine tasks remains valid.
6. Handoff approved slice, acceptance, prerequisites, verification, risks and next owner to Core/adapter.
No automatic issue assignment, messaging, calendar entries, merge or deployment.
