# BA → PO → Solution → Delivery

Use for a new product or material feature. For a small clear fix, use the Core compact path.
1. BA preserves idea/approved document revisions, identifies users, business rules and contradictions;
   load existing business-analysis/use-case/AC skills. Source/output register is authoritative.
2. PO uses mvp-definition and product-outcomes to propose a complete journey, in/out scope, minimum
   quality and success evidence. Resolve consequential unknowns with actual owner; no self-approval.
3. Pass reviewed FR/US/AC/NFR and decision status to installed Architecture discovery-to-design.
   If Architecture is not selected, Core spec uses the same constraints and records relevant choices.
4. Pass accepted solution boundaries, AC, dependencies and actual estimates to optional Delivery planning;
   absent Delivery, record a proportional task order in the OpenSpec change.
5. UI/UX can iterate with SA/PO; adapters implement accepted technical decisions. Verify and review
   against requirements/ADRs. Evidence and scope changes loop back to the owning role.
6. Carry source revisions, IDs, output paths, decisions, unresolved questions, actual checks and next
   owner in every handoff. A role label never creates a worker or approves a stakeholder decision.
